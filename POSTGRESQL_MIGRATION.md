# PostgreSQL Migration Guide

This document provides step-by-step instructions for migrating the diet-tracker-api from MS SQL Server to PostgreSQL.

## Prerequisites

- PostgreSQL 12 or higher installed
- Access to existing MS SQL Server database
- PowerShell 5.1 or higher (for migration scripts)
- PostgreSQL client tools (psql) installed

## Migration Steps

### 1. Update Application Configuration

The application has been updated to use PostgreSQL. Set these environment variables:

**For PostgreSQL:**
```bash
DB_HOST=localhost          # PostgreSQL server hostname
DB_PORT=5432              # PostgreSQL port (default: 5432)
DB_NAME=diettracker       # Database name
DB_USERNAME=postgres      # PostgreSQL username
DB_PASSWORD=yourpassword  # PostgreSQL password
```

**Previous MS SQL Server variables (no longer used):**
```bash
DATA_SOURCE              # Removed
INITIAL_CATALOG          # Removed
```

### 2. Create PostgreSQL Database

```sql
-- Connect to PostgreSQL as admin
psql -U postgres

-- Create database
CREATE DATABASE diettracker;

-- Create user (if needed)
CREATE USER diettracker_user WITH PASSWORD 'yourpassword';

-- Grant privileges
GRANT ALL PRIVILEGES ON DATABASE diettracker TO diettracker_user;
```

### 3. Run Migrations

```bash
# Set environment variables first
$env:DB_HOST="localhost"
$env:DB_PORT="5432"
$env:DB_NAME="diettracker"
$env:DB_USERNAME="postgres"
$env:DB_PASSWORD="yourpassword"

# Run migrations to create schema
dotnet ef database update
```

### 4. Export Data from MS SQL Server

Run the PowerShell export script:

```powershell
.\scripts\export-mssql-data.ps1 `
    -ServerName "your-sql-server.database.windows.net" `
    -DatabaseName "diettracker" `
    -Username "sqladmin" `
    -Password "yourpassword" `
    -OutputPath "C:\temp\diet-tracker-export"
```

For Windows Authentication:
```powershell
.\scripts\export-mssql-data.ps1 `
    -ServerName "localhost" `
    -DatabaseName "diettracker" `
    -OutputPath "C:\temp\diet-tracker-export"
```

**Alternative:** Use the T-SQL script `scripts/export-mssql-data.sql` if you prefer SQL Server Management Studio.

### 5. Import Data into PostgreSQL

Run the PowerShell import script:

```powershell
.\scripts\import-postgresql-data.ps1 `
    -Host "localhost" `
    -Port 5432 `
    -Database "diettracker" `
    -Username "postgres" `
    -Password "yourpassword" `
    -InputPath "C:\temp\diet-tracker-export"
```

### 6. Verify Data Migration

Connect to PostgreSQL and verify row counts:

```sql
SELECT 'User' as table_name, COUNT(*) FROM "User"
UNION ALL SELECT 'Plan', COUNT(*) FROM "Plan"
UNION ALL SELECT 'Fueling', COUNT(*) FROM "Fueling"
UNION ALL SELECT 'Victory', COUNT(*) FROM "Victory"
UNION ALL SELECT 'UserDay', COUNT(*) FROM "UserDay"
UNION ALL SELECT 'UserPlan', COUNT(*) FROM "UserPlan"
UNION ALL SELECT 'UserTracking', COUNT(*) FROM "UserTracking"
UNION ALL SELECT 'UserTrackingValue', COUNT(*) FROM "UserTrackingValue"
UNION ALL SELECT 'UserTrackingValueMetadata', COUNT(*) FROM "UserTrackingValueMetadata"
UNION ALL SELECT 'UserDailyTrackingValue', COUNT(*) FROM "UserDailyTrackingValue"
UNION ALL SELECT 'UserFueling', COUNT(*) FROM "UserFueling"
UNION ALL SELECT 'UserMeal', COUNT(*) FROM "UserMeal";
```

Compare these counts with your MS SQL Server database.

### 7. Test Application

```bash
# Build and run
dotnet build
dotnet run

# Or in Development mode
dotnet run --environment Development
```

Test API endpoints to ensure data is accessible.

## Key Changes Made

### Code Changes
1. **Package**: Replaced `Microsoft.EntityFrameworkCore.SqlServer` with `Npgsql.EntityFrameworkCore.PostgreSQL` (8.0.0)
2. **Program.cs**: Updated connection string format from SQL Server to PostgreSQL
3. **Migrations**: Deleted all SQL Server migrations, created new `InitialPostgreSQL` migration

### Data Type Mapping
- `nvarchar(max)` → `text`
- `nvarchar(n)` → `character varying(n)`
- `datetime2` → `timestamp without time zone`
- `date` → `date`
- `decimal(x,y)` → `numeric(x,y)`
- `bit` → `boolean`
- `IDENTITY` columns → `serial` / `GENERATED BY DEFAULT AS IDENTITY`

### No Breaking Changes
- All LINQ queries work unchanged
- No SQL Server-specific functions were used
- Composite keys work identically
- Foreign key relationships preserved

## Troubleshooting

### Cannot connect to PostgreSQL
```bash
# Check PostgreSQL is running
sudo systemctl status postgresql  # Linux
Get-Service postgresql*           # Windows

# Test connection
psql -h localhost -U postgres -d diettracker
```

### Import fails with permission errors
```sql
-- Grant permissions
GRANT ALL PRIVILEGES ON ALL TABLES IN SCHEMA public TO diettracker_user;
GRANT ALL PRIVILEGES ON ALL SEQUENCES IN SCHEMA public TO diettracker_user;
```

### Identity sequence issues
If auto-increment IDs aren't working after import:
```sql
-- Reset sequences for tables with IDENTITY columns
SELECT setval(pg_get_serial_sequence('"Plan"', 'PlanId'), (SELECT MAX("PlanId") FROM "Plan"));
SELECT setval(pg_get_serial_sequence('"Fueling"', 'FuelingId'), (SELECT MAX("FuelingId") FROM "Fueling"));
-- Repeat for other identity columns
```

## Rollback Plan

If you need to revert to SQL Server:

1. Keep original SQL Server database intact during testing
2. Revert code changes:
   ```bash
   git revert <commit-hash>
   ```
3. Restore SQL Server packages
4. Run original migrations

## Performance Tuning (Optional)

After migration, consider these PostgreSQL optimizations:

```sql
-- Create indexes on foreign keys (if not auto-created)
CREATE INDEX IF NOT EXISTS idx_userfueling_userid ON "UserFueling"("UserId");
CREATE INDEX IF NOT EXISTS idx_usermeal_userid ON "UserMeal"("UserId");

-- Analyze tables for query planner
ANALYZE;

-- Enable auto-vacuum (usually default)
ALTER TABLE "UserDay" SET (autovacuum_enabled = true);
```

## Support

For issues:
1. Check PostgreSQL logs: `/var/log/postgresql/` (Linux) or Event Viewer (Windows)
2. Enable detailed EF Core logging: `"Microsoft.EntityFrameworkCore": "Information"` in appsettings
3. Verify connection string format and credentials
